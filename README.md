# Tiger Run

[English](README.md) | [中文](README.zh-CN.md)

Tiger Run is a Windows desktop HTTP/HTTPS debugging proxy. It exposes one proxy address for browsers, Windows apps, and iOS/Android Wi-Fi proxy settings, with a local Root CA, HTTPS CONNECT interception, request/response inspection, quick copy actions, and HAR export.

## Features

- HTTP/HTTPS proxy server, listening on `0.0.0.0:8080` by default
- HTTPS MITM with a local Root CA and dynamically generated certificates
- Certificate download page: `http://<computer-ip>:8080/cert`
- One-click Windows per-user system proxy enable/disable
- One-click Root CA installation for the current Windows user
- Chrome extension for browser-only proxy switching
- Upstream proxy chaining for local gateways and enterprise proxies
- Request list, method filter, search, and detailed inspection
- One-click copy for headers, bodies, raw messages, URLs, and cURL commands
- HAR export with an “open file location” action
- Reserved architecture for future TUN/VPN mode

## Use Cases

- Debug HTTP/HTTPS traffic from websites, desktop apps, and mobile apps
- Inspect query parameters, cookies, headers, response bodies, and status codes
- Route only Chrome through the proxy without changing the system proxy
- Keep capturing traffic while routing outbound requests through an upstream proxy
- Export HAR files or copy cURL commands for QA and API debugging

## Quick Start

Local browsers or Windows apps:

```text
Proxy host: 127.0.0.1
Proxy port: 8080
```

iOS / Android:

```text
Wi-Fi proxy: <computer-lan-ip>:8080
Certificate URL: http://<computer-lan-ip>:8080/cert
```

## Chrome Extension

To route only Chrome through Tiger Run:

1. Open `chrome://extensions/`
2. Enable “Developer mode”
3. Load the [chrome-extension](chrome-extension) directory
4. Click “Enable Chrome Proxy” in the extension popup

This does not change the Windows system proxy. Captured traffic still appears in the Tiger Run desktop app.

## HTTPS Certificate

HTTPS decryption requires the target device to trust Tiger Run’s local Root CA.

### Windows

Click “Install to Windows” in the desktop app. The certificate is installed into the current user’s Root CA store.

### iOS

1. Connect the iPhone and computer to the same Wi-Fi
2. Set the iPhone Wi-Fi proxy to `<computer-ip>:8080`
3. Open `http://<computer-ip>:8080/cert` in Safari
4. Download the profile
5. Go to `Settings` -> `General` -> `VPN & Device Management` and install it
6. Go to `Settings` -> `General` -> `About` -> `Certificate Trust Settings`
7. Enable full trust for `老虎快跑 Local Debugging Root CA`

### Android

Android 6 and below usually trust user-installed CAs more easily. Android 7.0+ does not trust user CAs by default, so many third-party apps can be proxied but not decrypted.

For your own Android app, configure `network_security_config` in debug builds to trust user CAs. For third-party apps with SSL Pinning, you usually need root, a system CA installation, a debug build, or tools such as Frida/Objection.

## Upstream Proxy

If your machine needs to route outbound traffic through another local or corporate proxy, set the upstream proxy in the sidebar:

```text
http://127.0.0.1:7890
```

Traffic path:

```text
Chrome / Windows apps / mobile devices -> Tiger Run -> Upstream proxy -> Internet
```

Tiger Run can still capture traffic while the upstream proxy handles the outbound connection.

## Run From Source

Requirements:

- Go `1.25+`
- Node.js `18+`
- npm
- Wails v2 CLI

```powershell
go test ./...

cd frontend
npm install
npm run build

cd ..
wails dev
```

## Build Windows exe

Use the project build script:

```powershell
.\scripts\build-windows.ps1
```

Output:

```text
build/bin/老虎快跑.exe
```

The script generates app icons, frontend assets, Windows `.syso` resources, and then builds the executable. It also passes the Wails-required `production` build tag. Do not run plain `go build`, otherwise the app will show a Wails build tags error at startup.

## Icons

Icons are generated by [tools/icongen](tools/icongen):

```powershell
go run ./tools/icongen
```

## Limitations

- Does not bypass SSL Pinning
- Android 7.0+ third-party apps do not trust user CAs by default
- Current release focuses on HTTP/HTTPS proxy mode; TUN/VPN is reserved for future work
- HTTPS decryption depends on whether the target app trusts the local Root CA

## Security Notice

Tiger Run generates a local Root CA for HTTPS debugging. Use it only on your own devices, authorized test environments, or systems you are allowed to debug. Do not share the generated private key, and do not keep a debugging CA trusted in production environments.
